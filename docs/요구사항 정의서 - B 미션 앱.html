1개요

기획안의 핵심 가치인 “성취감은 극대화”를 맡습니다. 기록이 쌓이면 미션이 자동으로 성공하고, 달력이 채워지며 연속 달성이 늘어납니다.

시연에서 맡는 장면(1:30~2:30): 물·스쿼트 미션이 이미 성공한 2/3 상태에서, 점심 기록이 들어오면 ‘단백질 채우기’ 카드가 성공으로 바뀌며 폭죽이 한 번 터지고, 오늘 달력 칸에 완수 스탬프가 찍히며 연속 달성이 10일에서 11일로 늘어납니다.

5기능 요구사항

P0 = 시연 필수, P1 = 여유 시, P2 = 발표 이후. 10일차 최종 제출 때 P0은 모두 완료되어야 합니다.

ID기능요구사항우선순위완료 기준
B-F01미션 카탈로그도달형 4종: protein_min(단백질 {target_g}g), water_min(물 {target_ml}ml), squat_min(스쿼트 {target}개), steps_min({target}보). 코드·이름·슬롯·판정 규칙을 한 곳에 정의.P0카탈로그 밖 코드는 쓰지 않음
B-F02판정 함수순수 함수 evaluateMissions(missions, records, now) → 미션별 상태(in_progress/success)와 진행값(예: 32/60g). 매번 그날 기록 전체로 처음부터 계산.P0테스트 통과: 아침만 → 진행 중, 점심 추가 → 성공, 기록 삭제 → 다시 진행 중, 물·스쿼트·걸음 수 미달/도달
B-F03오늘의 미션 배정고정 세트(식단: 단백질 30g, 생활: 물 1,500ml, 운동: 스쿼트 30개). missionsRepo.assignIfEmpty로 그날 미션이 없을 때만 만듦.P0앱을 여러 번 열어도 미션이 중복되지 않음
B-F04로컬 저장소src/data/index.ts의 recordsRepo, missionsRepo를 AsyncStorage(JSON 배열)로 구현(6장 참고).P0앱을 껐다 켜도 미션 상태·달력이 유지됨. 저장소 테스트 통과
B-F05이벤트 구독 재판정onRecordsChanged를 구독해 이벤트가 오면 그날 기록 전체로 재판정하고, 바뀐 미션만 missionsRepo.update.P0목업 점심 기록 이벤트 후 1초 안에 카드 상태가 바뀜
B-F06미션 카드MissionCards: 식단·생활·운동 카드 3개, 진행률 막대와 숫자, 성공 표시, 상단에 “미션 n/3 완료”.P0로딩·빈 상태 처리 포함
B-F07성공 연출in_progress → success로 바뀌는 순간에만 폭죽 애니메이션 1회. 이미 연출한 미션 id를 기억해 재진입·재판정 때 반복하지 않음.P0같은 미션으로 폭죽이 두 번 나오지 않음
B-F08리워드 달력RewardCalendar: 월간 달력, 날짜별 성공 수(0~3)를 링으로, 3이면 완수 스탬프. listDayStatus 사용.P00/1/2/3 상태가 구분되고 3이면 스탬프. 오늘 칸이 3이 되는 순간 스탬프 연출
B-F09스트릭3개 모두 완수한 날이 끊김 없이 이어진 일수. 오늘이 아직 완수 전이면 어제부터 셈. 순수 함수 + 테스트, 달력 상단에 “연속 n일” 표시.P0테스트 통과: 오늘 미완료, 중간 하루 끊김, 오늘 완수
B-F10개발 도구 화면① 시연 시드: 어제까지 10일 연속 완수 + 오늘 물·스쿼트 성공·단백질 진행 중 + 아침 기록 ② 목업 점심 기록 넣기(+이벤트) ③ 전체 초기화 ④ JSON 보기.P0시드 → 점심 기록 버튼 한 번으로 2/3 → 3/3, 폭죽, 스탬프, 연속 11일
B-F11AI 1줄 코칭하루 기록과 미션 결과로 Gemini가 친근한 1문장 생성.P1버튼 또는 3/3 완수 시 1문장 표시
B-F12배지7일 연속 등 조건 달성 시 지급, 달력 화면에 배지 모음.P1조건 달성 시 1회 지급
B-F13회피형·구간형 미션튀김·가당 음료 피하기, 12시간 공복. 하루 마감 시점 판정.P2마감 판정 테스트 통과

6데이터 요구사항 (로컬 JSON)

저장 키 fitlog:daily_missions에 DailyMission 배열을, fitlog:records에 HealthRecord 배열을 JSON으로 저장합니다. 필드 이름은 contract와 똑같이 둡니다.

// AsyncStorage 키 "fitlog:daily_missions" 의 값 (JSON 배열)
[
  { "id": "a3e0…", "user_id": "local-user", "day_key": "2026-10-06",
    "slot": "diet", "mission_code": "protein_min", "params": { "target_g": 30 },
    "status": "in_progress", "achieved_at": null },
  { "id": "b71d…", "user_id": "local-user", "day_key": "2026-10-06",
    "slot": "life", "mission_code": "water_min", "params": { "target_ml": 1500 },
    "status": "success", "achieved_at": "2026-10-06T01:00:00.000Z" }
]
// "fitlog:records" 는 입력 앱과 같은 모양(HealthRecord 배열). 이 앱에서는 개발 도구로만 채움.

구현할 함수 (이름·모양 변경 금지)

함수하는 일
recordsRepo.*입력 앱과 같은 4개 함수(listByDay, insertMany, update, remove). 개발 도구에서 목업 기록 저장에 사용
missionsRepo.listByDay(dayKey)그날 미션 3개
missionsRepo.assignIfEmpty(dayKey, missions)그날 미션이 없을 때만 만들고(id·user_id·status=in_progress 채움), 있으면 기존 것을 그대로 돌려줌
missionsRepo.update(id, {status, achieved_at})판정 결과 저장
missionsRepo.listDayStatus(from, to)기간 안 날짜별 성공 수 {user_id, day_key, success_count} 목록(달력·스트릭용)

기능 코드(카드, 달력)는 AsyncStorage를 직접 부르지 않고 이 함수들만 씁니다. 그래야 통합 때 이 파일만 바꿔 Supabase로 옮길 수 있습니다.

9제출물과 일정

제출물

  • src/features/mission/, src/features/reward/ 전체
  • src/data/index.ts(로컬 저장소 구현)
  • docs/추가 패키지.md
  • package.json
  • 시연 장면 화면 녹화(시드 → 점심 기록 → 3/3 폭죽·스탬프·연속 11일)

제출 방법

  1. 프로젝트 폴더에서 src 폴더, docs 폴더, package.json 세 가지만 선택합니다.
  2. 마우스 오른쪽 버튼 → 압축(ZIP). 파일 이름은 이름_중간 또는 이름_최종(예: 홍현정_최종.zip).
  3. 시연 장면 화면 녹화 영상과 함께 멘토에게 전달합니다.

node_modules 폴더는 넣지 않습니다(용량이 매우 크고, 멘토가 다시 설치합니다).
