멘토 · team5

  • 오늘·달력 화면 조립, 시연

2왜 합칠 수 있나: 세 가지 약속

  1. 같은 공유 폴더 — 두 앱의 src/shared는 글자 하나까지 똑같습니다(데이터 모양, 날짜 계산, 이벤트, Gemini 호출). 개발자는 이 폴더를 수정하지 않습니다.
  2. 같은 저장소 함수 — 데이터는 src/data의 recordsRepo, missionsRepo로만 읽고 씁니다. 지금은 개발자가 휴대폰 로컬 저장소(JSON)로 구현하고, 통합 때 멘토가 이 파일만 Supabase 버전으로 바꿉니다. 기능 코드는 한 줄도 안 바뀝니다.
  3. 정해진 폴더와 컴포넌트 이름 — 기능 코드는 자기 기능 폴더에만 두고, 약속된 컴포넌트(InputPanel, Timeline, MissionCards, RewardCalendar)를 export합니다. 멘토는 폴더를 복사해 화면에 배치하기만 하면 됩니다.

4데이터 흐름

통합 후: 홍현정님 입력 → recordsRepo.insertMany → emitRecordsChanged 이벤트 → 이미경님 미션 카드가 이벤트를 받아 그날 기록 전체로 재판정 → missionsRepo.update → 폭죽·스탬프.

개발 중(앱이 따로일 때): 미션 앱에는 입력 기능이 없으므로, 이미경님은 개발 도구 버튼으로 목업 기록(src/shared/mocks/demo.ts)을 저장하고 이벤트를 직접 보내 같은 상황을 흉내 냅니다.

로컬 저장 키: fitlog:records, fitlog:daily_missions. 값은 JSON 배열이고 필드 이름은 DB 열 이름과 같습니다.

14~15일차리허설시연 리허설 참여시연 데이터 초기화, 3분 시나리오 2회 연속 성공

6제출 방법 (5일차 중간, 10일차 최종)

  1. 프로젝트 폴더에서 src 폴더, docs 폴더, package.json 세 가지만 선택합니다.
  2. 마우스 오른쪽 버튼 → 압축(ZIP). 파일 이름은 이름_중간 또는 이름_최종(예: 홍현정_최종.zip).
  3. 시연 장면 화면 녹화 영상과 함께 멘토에게 전달합니다.

node_modules 폴더는 넣지 않습니다(용량이 매우 크고, 멘토가 다시 설치합니다).

7공통 규칙

  • Expo Go에서 동작하는 패키지만 씁니다. 추가는 npx expo install로 하고 docs/추가 패키지.md에 기록합니다.
  • Gemini API 키는 코드·파일·메신저에 남기지 않고, 앱 설정 화면에만 입력합니다.
  • 판정·계산 로직은 화면과 분리한 순수 함수로 만들고 테스트를 함께 씁니다.
  • 매일 끝날 때 단톡방에 “오늘 한 것 / 막힌 것” 한 줄 공유. 30분 넘게 막히면 바로 멘토에게.
  • src/shared를 바꿔야 할 것 같으면 고치지 말고 멘토에게 먼저 말합니다. 멘토가 두 앱에 똑같이 반영해 다시 보냅니다.
