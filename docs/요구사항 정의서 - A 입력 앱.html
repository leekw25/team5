1개요

기획안의 핵심 가치인 “기록은 최소화”를 맡습니다. 사용자가 평소 말하듯 입력하면 음식·운동·칼로리·영양소가 자동으로 기록됩니다.

시연에서 맡는 장면(0:30~1:30): 발표자가 마이크 버튼을 누르고 “오늘 점심에 맘스터치 싸이버거 세트 먹고 콜라는 제로로 바꿨어”라고 말하면, 2초 안팎에 싸이버거·감자튀김·제로콜라 3개 항목이 타임라인에 나타납니다.

5기능 요구사항

P0 = 시연 필수, P1 = 여유 시, P2 = 발표 이후. 10일차 최종 제출 때 P0은 모두 완료되어야 합니다.

ID기능요구사항우선순위완료 기준
A-F01텍스트 입력 파싱입력창의 문장을 Gemini(generateJson)로 보내 contract의 ParseResult로 받는다. 음식 태그·운동 코드는 JSON 스키마의 enum으로 계약 목록 안에서만 고르게 한다. 온도 0.P0시연 문장 → 싸이버거·감자튀김·제로콜라 3개 항목. “스쿼트 15개 3세트 함” → code squat, sets 3, reps 15
A-F02음성 입력마이크 버튼을 누르면 녹음, 다시 누르면 종료. 녹음 파일을 Gemini에 바로 보내 인식과 파싱을 한 번에 한다(호출 1회).P0버튼 한 번으로 저장까지 끝남. 말 끝난 뒤 결과까지 2초 안팎(5회 측정 기록)
A-F03로컬 저장소src/data/index.ts의 recordsRepo를 AsyncStorage(JSON 배열)로 구현한다(6장 참고).P0앱을 껐다 켜도 기록이 남음. 저장소 테스트 통과
A-F04기록 변경 이벤트저장·수정·삭제가 성공한 뒤에만 emitRecordsChanged를 1회 호출한다(day_key, reason, record_ids).P0저장 1번에 이벤트 1번. 실패 시 이벤트 없음
A-F05오늘 타임라인Timeline: 그날 기록을 시간순 카드로 표시(시각, 음식·운동명, 칼로리, 단백질). 이벤트를 받으면 갱신.P0저장 직후 타임라인에 항목이 추가됨
A-F06실패·불확실 처리키 없음·인식 실패·빈 결과일 때 “다시 말하기 / 직접 입력” 안내. confidence가 낮은 항목은 저장하되 ‘확인 필요’ 표시.P0네트워크를 끄고 입력해도 앱이 멈추지 않고 안내가 나옴
A-F07빠른 기록 버튼최근 운동 칩 3개(기본: 스쿼트 15개×2세트, 푸시업 10개×2세트, 걷기 30분). 탭하면 AI 없이 바로 저장(source: quick).P0칩 한 번 탭으로 저장 + 이벤트 발행
A-F08시연 문장 응답 캐시시연 문장과 그 파싱 결과를 앱 안에 저장해 두고, 같은 문장이 들어오면 Gemini 대신 캐시를 쓴다(결과 고정용).P0같은 문장을 5번 넣어도 같은 수치. 비행기 모드에서도 시연 문장이 처리됨
A-F09개발 도구 화면저장된 JSON 보기, 전체 초기화, 시연용 아침 기록(mocks/demo.ts의 morningRecord) 넣기.P0시연 직전 1분 안에 초기 상태로 되돌릴 수 있음
A-F10단백질 수치 측정시연 문장을 캐시 없이 5번 파싱해 단백질 합계를 표로 기록, 멘토에게 전달(시연 목표값 결정용).P05회 결과표 제출
A-F11사진 식단 입력음식 사진 1장을 Gemini에 보내 메뉴와 탄·단·지 추정치로 저장(source: photo).P1사진 1장 → 기록 저장
A-F12걸음 수 자동 반영앱을 열 때 오늘 걸음 수를 읽어 하루 기록 1개로 덮어씀(source: health, code walking, steps).P1iPhone Expo Go에서 걸음 수 기록이 하루 1개만 유지됨
A-F13기록 수정·삭제타임라인 항목을 길게 눌러 수정·삭제. 성공 후 이벤트 발행.P2수정·삭제 후 이벤트 발행

6데이터 요구사항 (로컬 JSON)

저장 키 fitlog:records(LOCAL_KEYS.records)에 HealthRecord 배열을 JSON으로 저장합니다. 필드 이름은 contract와 똑같이 둡니다.

// AsyncStorage 키 "fitlog:records" 의 값 (JSON 배열)
[
  {
    "id": "6f1c…",                 // randomUUID()
    "user_id": "local-user",
    "day_key": "2026-10-06",       // toDayKey(new Date(occurred_at))
    "occurred_at": "2026-10-06T03:30:00.000Z",
    "kind": "meal",                // meal | exercise | water
    "source": "voice",             // voice | text | photo | quick | health
    "raw_text": "오늘 점심에 맘스터치 싸이버거 세트 먹고 콜라는 제로로 바꿨어",
    "foods": [ { "name": "싸이버거", "quantity": 1, "unit": "개", "kcal": 560,
                 "carb_g": 48, "protein_g": 24, "fat_g": 30, "tags": ["fried"] } ],
    "exercises": [],
    "water_ml": null,
    "confidence": 0.9,
    "created_at": "2026-10-06T03:30:03.000Z"
  }
]

구현할 함수 (RecordsRepo, 이름·모양 변경 금지)

함수하는 일
listByDay(dayKey)그날 기록을 occurred_at 오름차순으로 돌려줌
insertMany(records)id(randomUUID), user_id(LOCAL_USER_ID), day_key(toDayKey), created_at을 채워 저장하고 저장된 기록을 돌려줌
update(id, patch)해당 기록의 일부 필드를 바꿔 저장하고 바뀐 기록을 돌려줌(occurred_at이 바뀌면 day_key도 다시 계산)
remove(id)해당 기록 삭제

기능 코드(입력창, 타임라인)는 AsyncStorage를 직접 부르지 않고 이 함수들만 씁니다. 그래야 통합 때 이 파일만 바꿔 Supabase로 옮길 수 있습니다.

7외부 연동과 앱 내부 약속

대상내용
GeminigenerateJson(parts, schema). 텍스트는 {text}, 음성·사진은 {inline_data: {mime_type, data(base64)}}로 보냄. 녹음 형식이 Gemini 지원 형식인지 확인(안 되면 멘토에게)
기록 변경 이벤트(보냄)emitRecordsChanged({day_key, reason, record_ids}). 통합 후 미션 앱이 이 신호로 재판정함
날짜toDayKey(), addDays()만 사용. 직접 계산 금지
export 컴포넌트InputPanel(), Timeline({dayKey}) — src/features/input/index.tsx

9제출물과 일정

제출물

  • src/features/input/ 전체
  • src/data/index.ts(로컬 저장소 구현)
  • docs/추가 패키지.md
  • package.json
  • 시연 장면 화면 녹화(음성 입력 → 타임라인)
  • 단백질 5회 측정표, 음성 지연 5회 측정표

제출 방법

  1. 프로젝트 폴더에서 src 폴더, docs 폴더, package.json 세 가지만 선택합니다.
  2. 마우스 오른쪽 버튼 → 압축(ZIP). 파일 이름은 이름_중간 또는 이름_최종(예: 홍현정_최종.zip).
  3. 시연 장면 화면 녹화 영상과 함께 멘토에게 전달합니다.

node_modules 폴더는 넣지 않습니다(용량이 매우 크고, 멘토가 다시 설치합니다).
